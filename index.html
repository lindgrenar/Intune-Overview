Intune & Entra ID — Object, Configurable Aspect & Relationship Map

Every object is broken into its complete set of configurable aspects (where set, what it governs) and its explicit relationship states. Scope: Windows device management.

1. Identity
User
Entra ID User
Cloud identity (synced or cloud‑native). All assignments and policies resolve through its associated aspects.
Configurable Aspects
  • Directory Attributes (set in Entra admin/Graph) — Standard & extension attributes 1‑15, used by Dynamic Groups and Conditional Access user conditions.
  • License Assignments (Entra admin/Graph) — EMS/M365 E3/E5 enables MDM, Entra P1/P2 enables Dynamic Groups & CA.
  • Group Memberships (assigned/dynamic) — Resolves which policies/apps/profiles target the user. Includes Administrative Unit membership.
  • Device Affiliations — registeredOwner of Entra Device, primaryUser of Intune Managed Device, ownedDevices list.
  • Authentication Methods (Entra admin) — MFA, WHfB, passwordless; influences CA grant controls and PRT issuance.
  • Conditional Access Context — User risk level, sign‑in risk, device platform filter (evaluated during token request).
Relationship States
  • memberOf → Security Groups (assignment resolution)
  • registeredOwner → Entra Device
  • primaryUser → Intune Managed Device
User resource type ↗
Entra Device
Device Identity
Directory record of the endpoint; determines trust type, sign‑in capabilities, and stores the compliance verdict.
Configurable Aspects
  • Trust Type (set by join type) — Workplace (registered), AzureAD (joined), ServerAD (hybrid joined). Governs PRT and local auth.
  • Device Ownership — Personal/Corporate; affects compliance and CA.
  • Compliance & Management — isCompliant (written by Intune), isManaged (Intune MDM), deviceManagementMetadata.
  • Device Identifiers — deviceId, devicePhysicalIds (contains Autopilot ZTDId/OrderId), used in dynamic groups & filters.
  • Security & State — approximateLastSignIn, deviceTrustType, profileType (Autopilot indicator).
  • Group Memberships — Assigned/dynamic device groups; targeting resolution.
  • CA Device Filters — Device properties can be used in Conditional Access conditions.
Relationship States
  • registeredUsers / registeredOwners ← User
  • memberOf → Dynamic Device Groups (evaluation)
  • Holds Primary Refresh Token (PRT)
Device resource type ↗
Autopilot Registration
Autopilot Device
Pre‑provisioned hardware identity; exists before OOBE. Uploaded by OEM/Reseller/IT.
Configurable Aspects
  • Group Tag (set during upload/import) — Stored inside devicePhysicalIds as [OrderID]:<tag>. Drives Dynamic Group rules for profile assignment.
  • Enrollment Profile Name — Maps to the assigned Autopilot deployment profile.
  • Deployment Profile Assignment — Targets device groups (resolved via group tag rule).
  • Hardware Identity — Serial number, hardware hash, manufacturer, model.
Relationship States
  • devicePhysicalIds bridges to Entra Device
  • groupTag → Dynamic Group rule (e.g., [OrderID]:Sales)

2. Grouping & Scope
Security Group
Targeting Container
All assignments target a group (or virtual ‘All users/devices’). Resolves membership at assignment evaluation.
Configurable Aspects
  • Membership Type — Assigned (manual/Graph) or Dynamic (user/device rule). Dynamic requires Entra P1.
  • Membership Rule (dynamic syntax) — Evaluates user attributes or device properties continuously.
  • Role Assignments — RBAC roles can be assigned to groups (for admin delegation).
  • Administrative Unit Membership — Scopes the group's visibility for delegated admins.
Relationship States
  • members ← Users / Devices
  • Include/Exclude logic in assignments (exclude always wins)
  • Mixed user/device groups cause evaluation latency
Group resource type ↗
Assignment Filter
Intune Filter
Per‑assignment include/exclude rule evaluated at device check‑in. No Entra group sync delay.
Configurable Aspects
  • Rule Syntax — Kusto‑like, evaluates Intune device properties (OS version, SKU, model, manufacturer, enrollmentProfileName, etc.).
  • Platform — Limits to specific OS (Windows, macOS, etc.).
  • Assignment Linkage — Attached to a policy/app assignment as Include/Exclude.
Relationship States
  • Attached to assignment (Include/Exclude)
  • Evaluates Intune Device Properties directly

3. The Workloads
Windows Enrollment
Deployment Profiles
Controls device onboarding and OOBE experience. Assignments contain profile settings.
  • Autopilot Profiles — User‑Driven, Self‑Deploying, Pre‑Provisioned.
  • Autopilot v2 (Device Preparation) — Targets user groups, dynamic device grouping during OOBE, Win32/LOB mixing.
  • ESP — Enrollment Status Page; gates desktop until required apps/profiles are installed.
  • Restrictions — OS limits, personal device blocks, Device Categories.
Windows enrollment ↗
Configuration
Device Configuration
Settings pushed via MDM channel (CSP) or IME.
  • Settings Catalog — modern CSP standard.
  • Administrative Templates / Custom OMA‑URI — legacy/specialised.
  • Scripts & Remediations — PowerShell via IME.
  • Windows Update (WUfB) — rings, feature/quality/driver policies.
Device configuration ↗
Applications
Software Delivery
Intent‑based (Required/Available/Uninstall) with detection logic.
  • Win32 (.intunewin) — dependencies, supersedence, ≤30GB.
  • LOB — .msi, .appx, .msix.
  • Microsoft Store App (New) — Winget integration.
  • M365 Apps — C2R deployment.
  • Enterprise App Catalog (Intune Suite) — automated patching.
App management ↗
Endpoint Security
Security Profiles
Purpose‑built security; overlaps with Configuration (last writer wins per setting).
  • Antivirus, BitLocker, Firewall.
  • ASR & App Control (WDAC).
  • EDR onboarding → Defender for Endpoint.
  • Account Protection (WHfB, Credential Guard, LAPS).
  • EPM (Intune Suite).
Endpoint security ↗
Compliance Policy
Health & Risk Rules
Evaluates device state/risk and writes isCompliant to Entra Device.
  • OS version, encryption, secure boot, AV status.
  • Custom Compliance (PowerShell + JSON).
  • Defender risk score (Clear/Low/Medium/High).
  • Non‑compliance actions: mark, email, lock, retire.

4. Execution & Gates
Managed Device
Intune Managed Device
The physical/virtual machine; twin records: Entra Device + Intune managedDevice.
Configurable Aspects & Channels
  • MDM Channel (CSP) — Built‑in agent processing Settings Catalog, Custom OMA‑URI, restrictions.
  • IME Channel — Sidecar for Win32 app deployment and PowerShell scripts.
  • Compliance State — complianceState, last sync time; writes isCompliant to Entra Device.
  • Co‑management — Workload sliders (Intune/ConfigMgr) block Intune execution per area.
  • Device Identity Link — azureADDeviceId bridges to Entra Device object.
Relationship States
  • azureADDeviceId → Entra Device
  • isCompliant back‑sync → Entra Device
  • Co‑management workload slider blocks Intune control

Defender for Endpoint
MDE Service
Peer cloud service; receives EDR onboarding and sends risk telemetry via connector.
Bidirectional Signals
  • Receives onboarding blob from Intune Endpoint Security.
  • Sends Machine Risk Score → Intune Compliance / MAM policies.
  • Security Management for MDE — Manage security settings on devices not enrolled in Intune MDM.
MDE connector ↗
Conditional Access
Access Gate
Continuously evaluates token requests (CAE). Reads Intune’s compliance verdict.
Grant Controls
  • Require marked compliant — reads Entra Device isCompliant.
  • Require Hybrid Joined.
  • Require App Protection Policy (MAM grant).
  • Require Authentication Strength (phishing‑resistant MFA).
Relationship States
  • Targets Users; can filter by device conditions during auth.
